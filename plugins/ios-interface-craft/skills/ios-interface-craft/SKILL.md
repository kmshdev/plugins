# iOS interface craft

Choose the smallest useful set of specialists after inspecting the user goal, current screen, supported SDK, and existing design language. Use rendered previews or simulator captures to judge visual changes when available.

| Need | Specialist |
|---|---|
| Overall hierarchy, character, or design critique | [iOS Taste](../ios-taste/SKILL.md) |
| New screen layout and interaction | [iOS Design](../ios-design/SKILL.md) |
| Existing screen polish | [iOS UI Refactor](../ios-ui-refactor/SKILL.md) |
| Shared tokens and reusable styles | [iOS Design System](../ios-design-system/SKILL.md) |
| Platform conventions or accessibility review | [iOS HIG](../ios-hig/SKILL.md) |
| Coordinator-owned routes and modal state | [iOS Navigation](../ios-navigation/SKILL.md) |
| Motion and gesture continuity | [iOS Animations](../ios-animations/SKILL.md) |

Read only the selected specialists and their relevant references. Apply coordinator guidance only where the app already uses that architecture. Keep a design critique advisory; use the separate adversarial gate for a requested formal PASS/FAIL review.
